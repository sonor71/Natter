# NATTER: повторение символов — диагностика и управление генерацией

Если модель отвечает `ИНИНИНИНИ...` или `ОООООО...`, это может быть
**декодирующая петля**: наиболее вероятный токен повторяется снова и снова.
Особенно часто это заметно при `--temperature 0` (greedy decoding).

Но декодирующие петли — лишь **одна** возможная причина бессмыслицы.
Базовый NATTER обучался в первую очередь продолжать энциклопедическую прозу.
Он не освоил полноценное общение на русском. Штраф за повторы исправляет
некоторые петли, но не гарантирует связной или глубокой речи.

## Получение новой версии

После слияния PR:

```powershell
cd Y:\NATTER_CORE
git pull origin main
```

Обновление не изменяет `checkpoints/`, `artifacts/` или содержимое `data/`.
Текущий checkpoint будет загружаться без изменения архитектуры.

## Рекомендуемый диагностический прогон (без обучения)

```powershell
# Исходное поведение на прозе и диалоговом промпте
.\venv\Scripts\python.exe diagnose.py --stage base --temperature 0 --tokens 80 --seed 42

# Тот же checkpoint, с контролем повторов (deterministic)
.\venv\Scripts\python.exe diagnose.py --stage base --temperature 0 --tokens 80 --seed 42 --repetition-penalty 1.15 --no-repeat-ngram 3

# Семплирование + контроль повторов
.\venv\Scripts\python.exe diagnose.py --stage base --temperature 0.85 --top-k 40 --top-p 0.95 --tokens 80 --seed 42 --repetition-penalty 1.15 --no-repeat-ngram 3

# Разговорный интерфейс
.\venv\Scripts\python.exe chat.py --stage base --temperature 0.85 --top-k 40 --top-p 0.95 --repetition-penalty 1.15 --no-repeat-ngram 3
```

`chat.py` теперь использует эти настройки по умолчанию.

- **`--temperature 0`** всегда выбирает максимум вероятности; часто
  зацикливается на слабо обученной модели.
- **`--temperature 0.85`** допускает менее вероятные токены. Это не
  добавляет знаний; может производить разнообразный, но бессвязный текст.
- **`--repetition-penalty 1.15`** уменьшает вероятность уже выданных токенов;
  штраф применяется только к сгенерированной части, не к вопросу.
- **`--no-repeat-ngram 3`** запрещает повторение ранее выданных последовательностей
  из трёх токенов. Значение `0` выключает ограничение.
- **`--top-k 40`**, **`--top-p 0.95`** выбирают из ограниченного
  множества вероятных продолжений. `--top-p 1` выключает nucleus filter.

Чтобы увидеть исходное поведение, укажи
`--repetition-penalty 1 --no-repeat-ngram 0 --top-p 1`.

## Как отличить петлю декодирования от недообучения

Посмотри три начала текста в выводе `diagnose.py`:

- Начала обычного энциклопедического текста тоже бессвязны: базовая модель
  пока не обучилась русскому в достаточной мере; нужны дополнительные
  качественные данные, предобучение и сравнение `pretrain_best.pt` /
  `pretrain_last.pt`.
- Продолжения прозы более связны, а диалог `ПОЛЬЗОВАТЕЛЬ / НАТТЕР` плох:
  потребуется **отдельная стадия обучения диалогу** на проверенных парах.
- Токенизатор меняет кириллицу, массово появляются `<unk>` или NaN в logits:
  нужна техническая диагностика, а не слепое увеличение шагов.

Результаты должны оцениваться по содержательности, грамматике и сохранению
смысла **на новых текстах**, а не только по train/val loss.
