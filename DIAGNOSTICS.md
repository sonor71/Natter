# NATTER CORE — диагностика генерации

Это **проверка**, а не дополнительное обучение. Скрипт не изменяет веса,
токенизатор, `train.bin` или SQLite-память. Всё выполняется локально
с собственными checkpoint NATTER.

## Зачем

Базовая модель (`pretrain_*.pt`) обучалась предсказывать токены обычных
энциклопедических текстов. Однако `chat.py` подаёт инструкции и роли
«ПОЛЬЗОВАТЕЛЬ / НАТТЕР», которых почти не было в предобучении.

Поэтому низкий `val loss` на Википедии не гарантирует связных ответов в чате.
Мы сравниваем **продолжение обычной прозы** и **диалоговую подсказку**.

## Команды (PowerShell)

```powershell
cd Y:\NATTER_CORE

# Детерминированная генерация без семплирования; отчёт только в локальную logs/
.\venv\Scripts\python.exe diagnose.py --stage base --seed 42 --temperature 0 --tokens 80 --save

# Повторить с семплированием при фиксированном seed
.\venv\Scripts\python.exe diagnose.py --stage base --seed 42 --temperature 0.8 --tokens 80 --save

# Произвольное начало энциклопедического текста
.\venv\Scripts\python.exe diagnose.py --stage base --prompt "Философия изучает" --tokens 120 --temperature 0
```

Скрипт выводит SHA-совместимость checkpoint/токенизатора через проверку
`validate_checkpoint`, проверяет простой русскоязычный BPE round-trip,
наличие `<unk>`, NaN/Inf в предсказаниях, наиболее вероятные следующие токены
и фактические продолжения.

### Как читать результат

- **Обычный текст связный, диалог бессвязен:** фундаментальная проблема
  несовпадения формата предобучения и диалогового использования. Понадобится
  качественное диалоговое обучение на новых, проверенных примерах.
- **Оба варианта бессвязны:** языковая модель пока недостаточно обучена или
  имеет дефект в данных/токенизаторе/генерации. Вывод о причине без других
  измерений делать нельзя.
- **BPE roundtrip отличается:** возможно, дело в нормализации пробелов
  SentencePiece, но необычные изменения текста потребуют проверки.
- **NaN/Inf в logits:** скрипт завершится с ошибкой; нужно проверить
  checkpoint, обучение и стабильность чисел.

В `chat.py` и `diagnose.py` при генерации запрещены служебные токены
`PAD`, `BOS` и `UNK`. Это устраняет отдельный класс неправильных
выводов, но **не заменяет языкового или диалогового обучения**.

## Тесты без CUDA

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты используют случайно инициализированную крошечную модель и **не читают**
твои настоящие веса или личные документы.

Не загружай файлы `logs/` или `checkpoints/` в публичный GitHub.
Если делишься диагностикой, проверь отсутствие личной информации.
