# NATTER CORE — проверка освоения языка (без переобучения)

Текущие веса NATTER созданы с нуля. Предобучение проходит на статьях,
а не на диалогах. Поэтому ответы в `chat.py` могут быть бессвязными даже при
снижении `val loss`.

В проекте теперь есть две **разные** проверки:
- `diagnose.py` — произвольные начала текста, в том числе диалоговый промпт.
- `probe_language.py` — воспроизводимое продолжение **настоящих документов**:
  начало текста из `val`, подлинное продолжение, генерация NATTER и
  teacher-forced reference loss на продолжении. Валидирующие документы не
  используются во время обновления весов.

## Команды на RTX 3080 (PowerShell)

```powershell
cd Y:\NATTER_CORE
git pull origin main

# Проверить продолжение ранее не виденной статьи; только читает файлы.
.\venv\Scripts\python.exe probe_language.py --stage base --split val --examples 3 --seed 42 --save

# Проверить текущую способность продолжать тексты обучения.
.\venv\Scripts\python.exe probe_language.py --stage base --split train --examples 3 --seed 42

# Отдельно проверить диалоговые подсказки.
.\venv\Scripts\python.exe diagnose.py --stage base --temperature 0.85 --seed 42
```

Отчёты сохраняются только в `logs/` на локальном компьютере; GitHub их
игнорирует.

### Следующее обучение

```powershell
# Создаёт резервную копию старого best.pt при переходе к новому протоколу eval.
# Не изменяет BPE-словарь.
.\venv\Scripts\python.exe train.py --steps 1000
```

Теперь обычная оценка `train loss` и `val loss` использует одни и те же
заранее определённые случайным seed окна при **каждом** повторе измерения.
Это делает график сопоставимым в рамках неизменного корпуса. Протокол обозначен
в новых checkpoint как `eval_protocol = fixed-windows-v1`.

При первом продолжении с прежнего checkpoint:
1. старый `pretrain_best.pt` копируется в
   `archive/eval_protocol_history/`;
2. старое наименьшее значение `val loss` сбрасывается, потому что условия
   оценки изменились;
3. веса `pretrain_last.pt` и состояние оптимизатора загружаются как раньше.

**Важно:** после этой правки числа `val loss` не следует напрямую сравнивать
со значениями прежнего случайного протокола. Не нужно удалять или
переобучать токенизатор. Первые результаты сами по себе не обещают
осмысленный диалог и тем более философское мышление.

## Что мы пытаемся выяснить

- Если на настоящей статье NATTER выдаёт несвязные фрагменты, проблема не
  сводится к разговорному формату: языковая компетенция ещё низкая.
- Если проза стала связной, но диалоги нет, нужно обучать диалогам на
  разнообразных проверенных примерах.
- Если в сравнении с подлинными продолжениями модель систематически делает
  заметные ошибки, нужно исправлять качество корпуса и длительность
  обучения; никакой штраф за повторы не заменит этой работы.

Никаких сторонних предобученных моделей и API не требуется.
