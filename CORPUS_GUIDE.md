# NATTER CORE 1.1 — подготовка реального корпуса

**Нейросеть полностью собственная.** Не используются чужие языковые веса, облачные API и Ollama. Для серьёзного обучения нужно самостоятельно собрать много разнообразных законно используемых русских текстов.

## Что изменилось относительно 1.0

- `prepare.py` читает исходные документы по строкам, без загрузки всех текстов в RAM.
- Разделение на `train`/`val` — по целым документам и **стабильно по пути файла**. Добавление файлов не вызывает случайного перемешивания существующих документов.
- Точные копии документов пропускаются по нормализованному SHA-256. Повторяющиеся длинные абзацы **только отмечаются** в отчёте, автоматически не вырезаются. Смысловые и близкие копии документов этот скрипт не распознаёт: их нужно очищать отдельно.
- Для обучения BPE берётся ограниченная по размеру выборка из TRAIN-документов; VAL не используется.
- `train.bin` и `val.bin` записываются потоком (`uint32`), без хранения всего токенизированного корпуса в RAM. Большие книги не требуют загрузки целиком.
- `data/processed/corpus_report.json` показывает размер, источники, повторы и разбиение.

## Команды на Windows, диск Y:

```powershell
cd Y:\NATTER_CORE
.\venv\Scripts\python.exe prepare.py --dry-run
.\venv\Scripts\python.exe prepare.py
.\venv\Scripts\python.exe train.py --steps 100
```

**ВНИМАНИЕ: если `artifacts/tokenizer.model` уже создан на демонстрационных 12 текстах, а серьёзное обучение ещё не началось, лучше создать новый BPE на готовом большом корпусе.** Для этого сначала сохрани резервные копии `checkpoints/` и `artifacts/`, затем убери старые `.pt` из `checkpoints/` и используй `prepare.py --retrain-tokenizer`. Существующие веса с новым словарём несовместимы.

## Корпус

Клади `.txt` в `data/raw/` по одному документу на файл:

```
data/raw/
  encyclopedia/
  literature/
  philosophy/
  reasoning/
```

Формат UTF-8. Не добавляй автоматически сгенерированные и повторенные диалоги, личные документы без разрешения, чужие тексты с неподходящими условиями использования, рекламу и копии статей. Качественные параллельные дискуссии и критические комментарии для обучения философии важнее простого повторения Ницше.

Команда `prepare.py --dry-run` создаёт только `corpus_report.json`, не меняя веса или токенизатор. `prepare.py` создаёт BPE и токены, но **ничего не обучает в нейросети**.

После роста корпуса **с тем же словарём**: `prepare.py`, затем `train.py --steps 100 --allow-data-change`. Не используй `--allow-data-change`, если реально сменился словарь или архитектура.

## Что исправить позже

- Near-duplicate статьи, фрагменты одной книги в разных файлах, плагиат и дубли внутри текстов требуют более продвинутой дедупликации.
- Старый `train.py` берёт случайные окна из единого потока токенов (иногда окно пересекает границу документов). Это приемлемо как базовый эксперимент, но не оптимальная выборка для философских диалогов.
- Для оценки качества надо выделять независимые источники и фиксированный набор трудных вопросов, а не только смотреть на val loss.
- Содержательность Ницше и Батая не появится от самого факта запуска обучения; 10 млн токенов — лишь начало масштабирования, не гарантия философского мышления.
