# NATTER: текущие способности, многошаговая логика и многотуровое обучение

## 1. Реальное состояние, без обещаний

По исходному config.json (2026-10): собственный causal Transformer
с 6 блоками, 6 attention heads, hidden dim 384, контекстом 1024
BPE-токена и словарём 8192. По журналу пользователя: около 13.77 млн
параметров, pretraining checkpoint на шаге 3200 с val loss 3.5565.

**Данный Transformer НЕ имеет отдельного алгоритма многошагового
рассуждения, философского понимания, формирования мировоззрения или
сознания.** Generative inference предсказывает токены слева направо.
Dialogue SFT пока учился на одношаговых синтетических ответах, и реальные
разговоры содержат несвязные фразы. Память SQLite сохраняет сведения,
но не доказывает их истинность и не переписывает автоматически веса.

## 2. Функциональная доказательная логика — доступна прямо сейчас

Новый детерминированный модуль не требует checkpoint, GPU или API.

```powershell
cd Y:\NATTER_CORE
git pull origin main
.\venv\Scripts\python.exe reason.py --text "Если свобода предполагает выбор, то выбор имеет альтернативы; Если выбор имеет альтернативы, то за выбор можно отвечать; свобода предполагает выбор"
```

Система покажет **две последовательные проверяемые дедукции**
(modus ponens) и правила, из которых они следуют.

Отрицательные посылки:

```powershell
.\venv\Scripts\python.exe reason.py --text "Если а, то б; не б"
```

Это строгое следствие «не а» (modus tollens).

Проверка противоречия:

```powershell
.\venv\Scripts\python.exe reason.py --text "Если а, то б; а; не б"
```

В `chat.py` можно вводить те же выражения после `/logic `.

**Жёсткие ограничения:** атомарные фразы сопоставляются практически
посимвольно после нормализации регистра и пробелов. Модуль НЕ понимает,
что «свобода» и «автономия» близки по смыслу, НЕ оценивает истинность
посылок и НЕ строит доказательство из обыденного произвольного текста.
Он никогда не должен выдавать свою формальную дедукцию за интеллект модели.

## 3. Исправление многотурового обучения — реализация готова

Ранее одношаговая диалоговая модель не получала историю предыдущих вопросов.
Теперь `natter/multiturn.py` умеет:
- кодировать 2+ обмена `ПОЛЬЗОВАТЕЛЬ / НАТТЕР`;
- вычислять loss **только на ответах Наттера**;
- помечать каждый ответ завершающим токеном EOS;
- формировать на inference совместимый префикс с последними репликами;
- отбрасывать самые старые реплики, если контекст переполнен.

**Важно:** это исправление *формата данных*, а не немедленное улучшение
существующих весов. Для работающего нейросетевого общения необходим
существенный качественный корпус многотуровых разговоров и его обучение.

Для подготовки собственных диалогов положи два файла:

    Y:\NATTER_CORE\data\dialogues\multiturn\train.jsonl
    Y:\NATTER_CORE\data\dialogues\multiturn\val.jsonl

Каждая строка — независимый JSON с массивом обменов (2+):

```json
{"turns":[
 {"user":"Я утверждаю, что свобода исключает ответственность.","assistant":"Это спорный тезис. Если решение принято самостоятельно, то ответственность может быть следствием свободы, а не её противоположностью."},
 {"user":"Но разве общество не ограничивает мой выбор?","assistant":"Ограничивает. Здесь важно различать отсутствие внешних границ и способность выбирать внутри них. Какая именно свобода имеется в виду?"},
 {"user":"Речь о свободе морального решения.","assistant":"Тогда основной вопрос — в том, достаточно ли автономен человек, чтобы отвечать за выбранное действие при социальном давлении."}
]}
```

Не копируй этот пример сотни раз. Для полезной настройки нужны сотни
или тысячи **разных, качественно написанных, многотуровых** обсуждений,
а также независимая проверочная часть без утечек близких текстов.

Если файлы действительно подготовлены:

```powershell
.\venv\Scripts\python.exe train_dialogue.py --dataset multiturn --steps 500
.\venv\Scripts\python.exe chat.py --stage multiturn --temperature 0.7
```

Будет создан отдельный `checkpoints/dialogue_multiturn_best.pt`,
прежняя базовая модель остаётся без изменений. Если есть
`dialogue_tiny_chat_best.pt`, SFT стартует с неё, иначе — с
`pretrain_best.pt`. Новые записи уже не попадут автоматически
в обучение до пересоздания корпуса и нового запуска SFT.

## 4. Что необходимо для серьёзной философии

1. Более крупный разнообразный языковой корпус; на текущих ответах видно,
   что проблема связности предложения не решена.
2. Корпус отредактированных многошаговых обсуждений с
   контраргументами, уточнениями и пересмотром позиции.
3. Независимая проверка логики, интерпретации первоисточников и
   удержания контекста, а не просто token-level loss.
4. Подключение к проверяемой библиотеке философских первоисточников.
5. Масштабирование модели и вычислений **только на основе измеренных**
   ограничений и качества; не обещать «Ницше за ночь».

Модуль формальной логики реализует узкую доказательную функцию уже сейчас.
Задача общего философского интеллекта остаётся исследовательской.
