# NATTER CORE — собственная нейросеть с нуля

**Что это:** воспроизводимый локальный проект для обучения собственной языковой модели на PyTorch, с нуля, без чужих предобученных весов, облачных API, Ollama и платных подписок. Предусмотрены базовое обучение, отдельная настройка под диалог, долговременная память, локальная библиотека философских текстов и ручная проверка диалогов.

**Что это пока НЕ:** готовый философ уровня Ницше или Батая. Такой интеллект невозможно получить из 12 маленьких образцовых текстов. Сложность обучения с нуля определяется качеством и объёмом данных, временем обучения и исследовательской работой; на одной RTX 3080 обещать человеческий уровень рассуждения нельзя. Исходные файлы `data/raw/*.txt` нужны лишь для проверки работы системы. Они не служат достаточным корпусом.

## 1. Развёртывание в Windows (PowerShell)

1. Распакуй архив так, чтобы файл `C:\NATTER_CORE\train.py` существовал.
2. Установи Python 3.12, если его нет (с официального python.org).
3. В PowerShell:

```powershell
cd C:\NATTER_CORE
py -3.12 -m venv venv
.\venv\Scripts\python.exe -m pip install --upgrade pip
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

4. Установи **CUDA-версию PyTorch**. На странице https://pytorch.org/get-started/locally/ выбери Windows → Pip → Python → CUDA и запусти выданную команду, используя `C:\NATTER_CORE\venv\Scripts\python.exe` вместо `pip`. Пример формы (точный индекс зависит от актуальной страницы):

```powershell
.\venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu128
```

Проверь видеокарту:

```powershell
.\venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CUDA недоступна')"
```

Если CUDA недоступна, не запускай полноценное обучение на RTX 3080 до устранения проблемы.

## 2. Стандартные команды

Все команды выполняй из `C:\NATTER_CORE` в активном окружении или через `venv\Scripts\python.exe`:

```powershell
# Установка и проверка локального BPE, подготовка train/val по документам
.\venv\Scripts\python.exe prepare.py

# Обучение нашей модели с нуля. --steps значит ДОПОЛНИТЕЛЬНЫЕ шаги.
.\venv\Scripts\python.exe train.py --steps 500

# Следующие 500 шагов продолжат checkpoint, а не начнут всё заново
.\venv\Scripts\python.exe train.py --steps 500

# Индексация собственных философских текстов из library/books и library/notes
.\venv\Scripts\python.exe build_library.py

# Диалог (после хотя бы одного обучения)
.\venv\Scripts\python.exe chat.py

# Когда накопилось достаточно одобренных диалогов, отдельная стадия обучения диалогу
.\venv\Scripts\python.exe train_dialogue.py --steps 100

# Десять постоянных вопросов на рассуждение; ответы для ручной оценки в logs/
.\venv\Scripts\python.exe evaluate_dialogue.py
```

**Обрати внимание:** установленная по умолчанию модель имеет около нескольких десятков миллионов параметров и контекст 1024 токена. Даже обучать её на бессодержательных демонстрационных документах на сотнях шагов почти бесполезно — это только техническая проверка. Для смыслового прогресса нужен новый корпус, существенно больше и разнообразнее текущего. Фактическое число параметров выводит `train.py`.

## 3. Добавление данных

- `data/raw/`: отдельные UTF-8 `.txt` с разнообразными текстами для обучения языку. Не клади одни и те же диалоги много раз. Проверка разделяется по целым файлам, а не соседним символам.
- `data/dialogues/approved.jsonl`: только **одобренные** пары `{"user": "...", "assistant": "..."}`. Команда `/fix` дописывает правильный ответ после текущего вопроса.
- `library/books/`: книги, которыми ты имеешь право пользоваться; `library/notes/`: собственные конспекты и аргументы. Используются для локального поиска после `build_library.py`, **не меняют веса** и не заменяют обучения языку.
- `logs/`: все беседы и записи оценки. Логи не включаются в обучение автоматически.

**После добавления новых текстов:** `python prepare.py` (с тем же токенизатором), затем `python train.py --steps 500 --allow-data-change`. При обновлении корпуса лучшая ошибка сбрасывается, а сохранённый токенизатор остаётся прежним. Если хочешь пересоздать BPE-словарь, придётся также начать обучение весов сначала: IDs токенов несовместимы.

**Важно:** `prepare.py` удаляет точные копии документов по нормализованному хешу, но не выявляет смысловые дубликаты и почти одинаковые версии. Чистота корпуса — отдельная большая работа. Для нового, значительно более крупного корпуса желательно обучить новый BPE до начала серьёзного предобучения.

## 4. Работа с памятью и исправлениями

В `chat.py` команды:

- `/exit` — выйти.
- `/remember <факт>` — вручную записать подтверждённое сведение в локальную SQLite-память.
- `/position <тезис> | <аргументы> | <сомнения>` — сохранить твою структуру аргумента.
- `/mem` — вывести недавние записи.
- `/find <запрос>` — поиск по философской библиотеке с названием источника.
- `/fix <хороший ответ>` — записать исправленную пару пользователя и Наттера в `approved.jsonl` для будущего обучения.

Память пока **не проверяет достоверность** и не должна приниматься за доказательство, что у модели есть сознание, собственные переживания или сформировавшееся мировоззрение. Команда `/position` сохраняет сформулированную позицию, но не порождает её самостоятельно.

## 5. Файлы

- `natter/model.py` — обучаемый с нуля Transformer: RoPE, RMSNorm, SwiGLU, causal SDPA, tied embeddings.
- `natter/tokenizer.py` — BPE SentencePiece: словарь обучается только на твоём корпусе.
- `prepare.py` — подготовка данных и документный train/val split, бинарные токены.
- `train.py` — базовое предобучение, AdamW, gradient accumulation, CUDA AMP, лучшая и последняя контрольные точки.
- `train_dialogue.py` — обучение на одобренных ответах с маскированием промпта.
- `natter/library.py` — локальный BM25-поиск без предобученной нейросети, базовый лексический индекс.
- `natter/memory.py` — SQLite, записи с явного согласия пользователя.
- `evaluate_dialogue.py` — одинаковые вопросы на разных checkpoint, ручная оценка содержательности.

## 6. Ограничения и дальнейшая работа

У текущей модели нет KV-cache при генерации; длинные ответы будут медленнее. Индекс BM25 ищет совпадения слов, плохо обрабатывает синонимы и морфологию; цитаты необходимо проверять. Диалоговое дообучение на нескольких примерах может ухудшить качество. Без значительного корпуса и длительного обучения ответы будут случайными или заученными. Применение RoPE и SwiGLU не создаёт мышление само по себе.

Для задачи философского общения решающее значение имеет большой, качественный и законно полученный корпус, включающий естественный язык, аргументацию, научно-популярные и философские тексты, а затем — проверяемые многотуровые диалоги. На RTX 3080 возможна техническая и исследовательская разработка, но не гарантирован уровень сильной современной LLM.

**Следующие реальные инженерные задачи**: потоковая подготовка больших корпусов, оценка дедупликации и качества, подготовка десятков миллионов новых обучающих токенов, профилирование производительности, KV-cache, проверяемые ссылки на источники, более надёжный датасет многотуровых разговоров и автоматические тесты регрессии после переобучения.
